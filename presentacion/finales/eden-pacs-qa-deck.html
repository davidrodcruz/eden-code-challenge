Project Patriot no es un script suelto: es una plataforma. La arquitectura es escalable a múltiples equipos: cada equipo vive en tests/webui/teams/<team>/ con su propio config.yaml — URLs, browser y timeouts — y overrides por variables de entorno con prefijo PATRIOT_.

Sobre la capa de equipos, el core reutilizable: base_page, drivers y la lógica de ejecución CLI. Los patrones son estrictos: Page Object Model puro — todos los selectores viven en la página, como MprViewerPage — y separación total entre el comportamiento en Gherkin y la manipulación del DOM: los steps son wrappers finos que llaman a la página y adjuntan evidencia.

Agregar una herramienta nueva es tocar tres archivos con responsabilidades separadas; no se acopla lógica en una sola clase.

El canvas de Cornerstone3D es opaco para el DOM: los píxeles los dibuja la GPU y no se pueden inspeccionar. Por eso la estrategia de automatización arranca con una decisión de capas.

A nivel DOM, implementado: descubrimos que, aunque la imagen es WebGL puro, las mediciones y los textos se renderizan como overlays SVG con g[data-annotation-uid]. Asertamos sobre ese DOM — estabilidad en CI/CD sin la fragilidad de comparar imágenes del canvas — y evadimos la interceptación de eventos con inyección dinámica de CSS, pointer-events: none.

Enfoques alternativos: la validación de estado interno, inyectando JavaScript para consultar window.cornerstoneTools, será la siguiente iteración para precisión matemática de coordenadas. La regresión visual se evaluó para el pixel-perfect, pero se descartó temporalmente: el anti-aliasing de las GPUs varía entre entornos de CI y la vuelve frágil.

Fuera del alcance E2E: la validación sub-píxel de los datos DICOM y las pruebas de estrés de fugas de memoria en GPU se delegan a pruebas de componentes de bajo nivel y monitoreo de performance, priorizando velocidad y confiabilidad de la suite.

06 · Solución técnica

El canvas que interceptaba todo

Cornerstone3D renderiza sobre <canvas> que capturan los eventos de puntero: el clic nunca llegaba al menú circular.

Solución: Liberación del DOM
mpr_viewer.py
await page.add_style_tag(
  content="canvas { pointer-events: none !important; }"
)
try:
    await page.mouse.click(x, y)
finally:
    await canvas_style.remove()
01 · El Problema

Eventos secuestrados

El canvas de Cornerstone3D secuestra los pointer events: un clic que debería abrir el menú circular termina en el canvas.

El menú radial usa transform: rotate/skew, lo que hace inestables las coordenadas absolutas del layout.

02 · La Robustez

Firma única del SVG

Cada herramienta se identifica por la firma única del atributo d del <path>, inmune a las coordenadas absolutas del layout.

d="M4 9a1 1 0 0 1 1-1h14"Ruler

El reto técnico más duro fue el menú circular. Cornerstone3D renderiza en canvas que interceptan todos los eventos de puntero: un click normal de Playwright aterriza en el canvas y nunca llega al menú.

La solución: inyectar CSS dinámicamente que evada punteros en los canvas — canvas { pointer-events: none !important } — dentro de un try/finally para no dejar estado residual en el DOM.

Pero además, los ítems del submenú usan transformaciones CSS rotate/skew que vuelven inestables las coordenadas: en vez de clickear por posición, identificamos cada herramienta por la firma única del atributo d del SVG path. La regla, por ejemplo, empieza con M4 9a1 1 0 0 1 1-1h14. Resultado: selección determinista, sin depender del layout.

09 · Defectos críticos reportados

Bugs accionables, con severidad clínica

Bug 01 · Renderización Severidad alta
ContextoEn la vista 3D, el visor degrada el Level of Detail a nube de puntos al abrir el menú circular para liberar recursos.
DefectoAl cerrarlo, no se dispara el evento de actualización visual (Render Update Failure): el modelo queda pixelado y no recupera resolución.
ImpactoOculta detalles anatómicos críticos durante la lectura volumétrica.
Bug 02 · UI Severidad media
ContextoInteracción del usuario en las proximidades de los bordes del viewport.
DefectoEl menú circular se renderiza sin calcular los límites del contenedor: las herramientas de esos cuadrantes quedan recortadas (clipped) fuera de pantalla.
ImpactoHerramientas inalcanzables en regiones críticas del lienzo clínico.
ReproduciblesCon evidencia en AllureEncontrados antes que un radiólogo en producción

Dos defectos críticos que la suite o la exploración dejaron en evidencia. Primero, severidad alta: en la vista 3D, al abrir el menú circular el visor degrada el nivel de detalle a una nube de puntos para liberar recursos; al cerrarlo, el evento de actualización visual no se dispara — Render Update Failure — y el modelo queda pixelado indefinidamente.

El impacto clínico es directo: ocultar detalles anatómicos en lectura volumétrica. Segundo, severidad media: el menú circular no calcula los límites del contenedor; al hacer clic derecho cerca de las esquinas del canvas, las herramientas quedan recortadas fuera de pantalla.

Ambos son accionables y reproducibles, con evidencia adjunta en el reporte. El valor del QA es encontrarlos antes que un radiólogo en producción.

10 · UX Feedback

Fricción cognitiva en el flujo clínico

El QA como voz del usuario clínico: hallazgo → impacto → recomendación accionable.

Fricción 01

Herramienta Flecha · modelo mental invertido

EsperadoOrigen → Destino
ActualDestino → Origen
HallazgoEl primer clic define la punta (destino); el arrastre define la cola (origen).
ImpactoRompe el estándar y la memoria muscular: fricción inmediata y trazos erróneos en el uso inicial.
RecomendaciónInvertir la lógica de trazado.
Fricción 02

Anotación de texto · acoplamiento forzado

EsperadoTexto libre directo
ActualVector obligatorio + etiqueta
HallazgoNo existe opción de texto libre: para insertar una etiqueta hay que dibujar primero una flecha.
ImpactoSatura el lienzo clínico y obliga a dibujar vectores sobre los tejidos para anotar nomenclatura.
RecomendaciónDesacoplar texto de vector en el menú circular.

Salimos del renderizado y miramos la experiencia del radiólogo. Hallazgo uno: la herramienta flecha invierte el modelo mental. El primer clic define la punta — el destino — y el arrastre define la cola.

La industria y la memoria muscular esperan Origen → Destino; el resultado es fricción inmediata y trazos erróneos. Recomendación: invertir la lógica de trazado.

Hallazgo dos: el menú circular no ofrece texto libre; para insertar una etiqueta hay que dibujar primero una flecha. Ese acoplamiento satura el lienzo clínico y obliga a dibujar vectores sobre tejidos solo para anotar una nomenclatura. Recomendación: desacoplar el texto del vector y ofrecer la etiqueta como opción independiente. El QA es la voz del usuario clínico.
